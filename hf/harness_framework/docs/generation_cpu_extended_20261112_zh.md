## 授权与固定边界

用户明确同意本轮将单次总输出预算提高到 32,768 tokens、绝对等待期限延长到 1,200 秒，模型保持 `gpt-6.1-sol / max`。该授权记录在 `outputs/generation_cpu_extended_20261112_setup/budget_authorization.json`，不追溯改变旧请求的超预算判决。

默认 `standard` 配置仍限制为 16,384 tokens 和最长 600 秒；新实验显式冻结 `budget_profile=extended` 与实际请求值。选择扩展配置本身不会自动提高默认值。服务报告的总输出仍包含推理 tokens，超过本轮 32,768 上限仍须拒绝；用量缺失不能记为零费用。

科学门槛、候选运行的 300 秒时限、2 GiB 每进程地址空间限制、最多 8 轮及开发集均未放宽。本轮关闭生成服务的网络自动重试；数值失败必须保留证据，并进入新的生成轮次。候选代码只能由模型修改，控制器不得手工补写答案。

## 启动前的证据

新旧回归共 **235 项通过**；测试期间控制器及测试源码身份未变化。JSON 和 SSE 均使用父进程绝对截止时间、进程组清理及有界匿名诊断，扩展等待的模拟测试不会实际等候 20 分钟。

远端 CPU 命名空间环境复核通过，镜像、运行库和 rootfs 清单与此前合格环境一致。候选继续使用隔离镜像内 Python；无网络、无 API 密钥、无参考或验证器访问。限制口径仍是每进程地址空间、真实 UID 的进程数及 CPU 亲和性，不宣称为 cgroup 总内存或 CPU 配额。

执行配置去除了 GPU/nsys 字段，并冻结 `stop_before_gpu=true`。CPU 通过后应进入 `waiting_for_gpu_authorization`，不会发起 GPU 预检，也不会消费保留集。
