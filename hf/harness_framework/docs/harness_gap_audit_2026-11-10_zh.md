## 2. 集群现在能做什么

集群有 5 个任务定义：直接 RHF 基准、直接 J/K 的 CPU 并行、RI-J/COSX 及 SCF 并行、水簇规模预检、水簇一次 J/K。

`MethodSpec → run_candidate → MetricReport → AcceptanceGate → archive_acceptance` 已经可以工作。它能执行固定命令、设置超时、保存标准输出和错误、分类失败、读取候选 JSON 指标、按门槛判定，并保存最新验收、历史验收副本和 `experiments.jsonl`。对应 [CLI](audits/2026-11-10/cluster-source/harness_engineering/cli.py)、[运行器](audits/2026-11-10/cluster-source/harness_engineering/runner.py)、[验收规则](audits/2026-11-10/cluster-source/harness_engineering/models.py)、[归档](audits/2026-11-10/cluster-source/harness_engineering/archive.py)。

这些能力可以评估人工或外部代理预先写好的候选；它本身不会提出优化、调用模型、生成代码或持续搜索。

计算代码已有闭壳层分子 RHF、直接 J/K、Schwarz 筛选、增量 Fock、RI-J/COSX、DIIS、CPU 线程并行、内存预估及部分 CuPy 收缩。完整 SCF 仍使用稠密广义对角化。**存在 GPU 代码，不等于 harness 已验证 GPU 求解性能。**

当前模块和生产求解路径不同：[hf.py](audits/2026-11-10/cluster-source/hf.py) 的 `get_jk("rijcosx")` 在 1586–1587 行调用自研 RI-J/COSX，`solve_rhf("rijcosx")` 在 1697–1701 行调用 PySCF DF/SGX。优化模块不会自动改善这条生产 SCF 路径，必须用实际调用关系和端到端复测确认。

## 4. 本地较新版本增加了什么

本地有 10 个任务和 12 条历史记录，增加了初猜对角化、近线性 J/K、一次训练迭代、占据密度 oracle/budget，以及 `loop.py`、`training_hf.py`、`generated/occupy_density.py`。这些文件在此次核验的集群项目目录中不存在；直接在集群使用这些本地流程会先遇到版本不一致。

本地 `loop.py` 每次只执行一次 oracle → budget，再返回 `accept`、`fix_once`、`revert`、`keep_correct_candidate` 或 `stop`。这些是动作建议，没有实际模型调用、代码修改、修复或回滚。CLI 不加载历史投影和累计修复次数，因此跨轮停滞规则也不会自行生效。`experiments.jsonl` 目前主要是记录，尚未成为自动优化的反馈输入。

当前生成槽仍直接调用稠密参照 `occupy_density_reference`。最新本地 oracle 密度误差为 0；budget 拒绝，三个系列的对角化外推分别是水 **117.861 h**、苯 **144.265 h**、烷烃 **100.218 h**，均超过模块门槛 48 h。完整 J+K+密度更新的外推分别为 **127.685 h、173.245 h、187.301 h**。这些是本地历史结果，未证明相同流程已在集群运行。

## 5. 与目标的实质差距及完成标准

### P0：让科学与性能验收值得信任

**现状与影响：** 集群 gate 的浮点比较会放过 NaN；布尔检查只认 `is False`，会放过错误类型。指标由候选自行写入，runner 与候选共用权限、继承全部环境，没有只读评测区。任务 JSON 的 cases 没有统一注入实际评测，许多案例由候选脚本硬编码。自动生成一旦进入，这些问题会降低验收结果的可信度。

**完成标准：** 所有受约束数值都必须类型正确且有限；必需布尔值必须是真布尔且为真；缺失或畸形报告应拒绝。可信评测器从候选实际输出重新计算误差和性能，任务规格决定真正运行的案例。候选仅可修改允许的算法文件，参考实现、门槛和评测器在候选之外保护。加入保留测试、真实 Fock/S 快照、小能隙及困难输入；在更大规模验证占据子空间残差、幂等性、电子数及最终能量与收敛。

### P1：实现真正自主的生成—反馈—优化执行器

**现状与影响：** 集群没有生成接口和循环，本地只有一轮验收包装。没有从历史选取最佳候选、实际执行修复/回滚、保存累计轮数、预算和停滞状态的执行器。

**完成标准：** 外层执行器能够读取固定目标和历史，选择待优化模块，调用模型生成受限补丁，在独立候选目录运行可信测试，分析拒绝原因，执行修复、回滚或晋升，并持久化状态。模型与具体框架可替换，科学标准由独立评测器控制。每个候选保存源码/补丁、hash、父候选、任务版本、依赖与硬件指纹、原始测量和决策理由；重启后可续跑并恢复最近正确与最快合格候选。

建议首个自主验收演示：固定一个算法接口，连续运行多轮而无需人工改代码；实际展示候选生成、数值拒绝、恢复正确版本、性能改进判定和中断续跑。单纯打印动作名称不算完成。

### P2：把模块优化接到真正的生产求解与总预算

**现状与影响：** 当前自研 J/K 与生产 DF/SGX 路径不一致。一次训练迭代不等于收敛 SCF；电子数、对称性和有限值也不足以证明密度占据正确。近线性 J/K 的局域分支缺少同尺寸高精度参照，不能仅由低标度指数认定精度不变。

仓库已有长期指标为约 **50,000 基函数、20 次 SCF 迭代、收敛 1e-8、48 小时内**，见集群 [scale 任务](audits/2026-11-10/cluster-source/harness/tasks/water_cluster_ccpvtz_scale.json)。这不是本次审计新设的目标；其中“收敛 1e-8”的物理量和单位仍需明确。

本地预算只验收对角化分量 ≤48 h，没有验收总时长。当前烷烃 J+K 的外推已约 **87.08 h**；即使把对角化耗时降为零，该组外推仍超过 48 h。只优化对角化不能覆盖总目标。

**完成标准：** 明确并统一候选进入生产的调用路径。以完整收敛求解为最终验收，定义能量、密度/残差、精度及全部阶段的总耗时和峰值内存。小规模用同方法同精度的成熟实现校验，中规模进行可重复的完整 SCF，生产规模逐级实测。对筛选、局域化、网格和近似引入的误差单独设预算。

### P3：证明高性能，再扩展软件适用范围

**现状与影响：** 历史 speedup 主要是自家串并行比较；没有当前集群硬件上的可复现基准。大规模结果有跳过与两点外推，尚无五万基函数实测。现有 harness 未覆盖 GPU、跨节点、调度、抢占恢复。当前任务集中于闭壳层分子 RHF，不能据此证明覆盖通用第一性原理软件的全部需求。

**完成标准：** 先在目标集群固定硬件和软件环境，分别测正确性、完整求解时间、重复测量波动与峰值内存，再与同方法、同精度、同资源的成熟基线比较。标明每档“完成/跳过/失败/外推”，覆盖目标档才可宣布规模目标达成。之后按实际需求扩展 GPU、分布式及其他物理方法；DFT、UHF、周期体系、力/应力或后 HF 是否需要，应写进明确的任务范围，不能以 RHF 小体系结果代替。

## 6. 建议实施顺序

1. 保存并统一经过审核的代码版本，让集群与本地的任务、接口和评测器可追溯；补上非有限数值和布尔类型验收，并建立可信评测与候选隔离。
2. 用真实 Fock/S 与困难案例固定第一个优化接口，统一模块到生产的调用路径，记录可信基线及完整预算。
3. 接上外层自主执行器、候选快照、历史状态和真实回滚，先证明单模块自主闭环可以持续运行。
4. 把合格候选纳入中规模完整 SCF，验证总时长、最终科学精度和内存，再逐级扩到目标规模与硬件。

本次已完成的是上述项目目录的现状核验与差距评估。自主优化系统和生产规模性能目标仍需按这些完成标准建设与验证。
