# 自动生成电子结构方法 Harness：实现与当前验收状态

日期：2026-11-11。当前结论是 **框架已实现，本地测试通过；新生成方法的容器与 GPU 科学验收待开发机可用后执行**。旧 `gpu_hf.py` 的成功记录没有用于替代本框架的验收。

## 已实现

新增 `harness_engineering/generation/`，公共入口为 `run`、`resume`、`evaluate`。完整使用说明见根目录 `README_GENERATION_zh.md`。

- **固定规格与从空开始。** 初始候选只包含两个 `NotImplementedError` 接口；开发集、保留集、公式、依赖、阈值、模型和执行配置在生成前固定。
- **可信科学层。** 独立 PySCF 子进程准备积分与参考；候选仅拿到积分。验证器从原始矩阵重算 16 项指标，拒绝空集、漏项、重复、未知状态、伪收敛、非有限数据和错误类型。
- **物理输入和运行身份。** 保存解析后几何、轨道/辅助基组与张量约定；相同输入的改名、单位转换、原子重排不能冒充新保留案例。记录实际加载的 NumPy、SciPy、PySCF/积分原生库、Python，以及容器/GPU 运行依赖的路径和 SHA256。
- **Responses 生成与真实回滚。** 单文件结构化补丁、原子应用、修改依据、原始请求/响应/用量、最多八轮、临时网络故障有限重试。失败候选保留，活动源码实际回滚；不是只返回一个 `revert` 字符串。
- **持久恢复与保留集隔离。** 每轮和每例的已完成证据即时固定哈希。中断后恢复完整回执，或者保留孤儿输出后重新执行；最终验收开始后不再向模型反馈结果。共享保留集使用登记防止同一物理保留集被另一个实验反复调参。
- **Linux 容器和 SSH 执行端。** 无网络、非 root、只读输入、受限资源，不安装参考求解器；只传候选、积分、worker 和选项。缺少合格运行时不会回退宿主执行。
- **GPU 阶段证明。** 最终 GPU 需要 Nsight Systems 的 CUDA/NVTX 追踪，逐阶段核对关联 kernel，并结合设备本征求解观察；只生成 CuPy 输出不够。
- **结果安全读取。** 候选 NPZ 在分配和解压前做包目录、头部、类型、形状和字节限制，避免压缩炸弹进入可信评测进程。

## 当前证据

完整本地回归输出：`outputs/generation_framework_validation/all_tests.log`。

本地测试覆盖生成接口异常、预算、原子写入、恢复、回滚、保留集泄漏、历史证据篡改、GPU 追踪缺失、错误矩阵、伪收敛及压缩包攻击，也包含原有 HF 的回归。科学验证器使用真实独立 PySCF exact/DF 参考；控制器、Docker 命令和 GPU 追踪逻辑的模拟测试不代表真实容器或 GPU 已通过。

开发集 12 组和保留集 8 组的可信参考计算已经预检收敛。附加属性关卡使用刚体移动 exact/DF、DF 分块 1/7 及单次迭代契约。单次迭代记录明确排除最终能量、参考密度和驻点残差门槛，其他物理状态一致性仍须满足；不能把它算作完整收敛计算。

本机真实运行 `run` 的结果为 `waiting_for_environment`，退出码 2、生成轮数 0、未调用模型。原因是本机没有 Docker。当前源码对应的证据在 `outputs/generation_framework_validation/no_container_final/`。

用户提供的 SSH 执行机此前可达，但批处理登录返回 `Permission denied (publickey)`。随后用户说明开发机暂不可用，要求先完成其他工作；此后没有继续访问该开发机。

## 真实 API 检查

用户授权使用已有 Responses 服务，模型固定为 `gpt-6.1-sol`：

1. `ultra` 请求被服务以 HTTP 400 明确拒绝。原始记录在 `api_generation_smoke/`，没有自动降级。
2. 用户随后确认改用 `max`。真实请求从空接口生成了 **285 行 RHF 候选**，保留在 `api_generation_max/candidate/solution.py`；没有人工修改，也没有在宿主直接执行。
3. 服务报告的输出用量为 **23,663 tokens**，高于请求中的 **16,384** 上限，并且响应 `max_output_tokens=null`。因此该结果不能作为符合预算的生成成功，也不能作为科学验收成功。
4. 发现此问题后补上用量检查与控制器暂停逻辑：越上限返回 `output_budget_exceeded`，不应用代码、不自动重试或付费生成下一轮。供应商已经发生的用量无法由客户端撤销；完整原始数据保留。
5. 用修复后的生成器 **离线重放同一真实响应**，确认返回 `output_budget_exceeded`、没有生成可应用补丁、没有发起新网络请求。证据在 `provider_budget_replay_final/verdict.json`。较早的重放还发现供应商用量扩展包含嵌套数组，已修复并增加回归测试，失败记录亦保留。

上述 API 子目录均位于 `outputs/generation_framework_validation/`。原始请求、响应、差异、源码哈希和用量可直接审阅。密钥没有写入候选、配置或证据文件。

## 设计来源与范围
